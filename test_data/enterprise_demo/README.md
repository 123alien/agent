# 企业级招投标智能核验 Demo 数据集

本数据集以公开典型案件中常见的风险特征为原型重新构造。全部企业、人员、联系方式、项目编号和业务数据均为虚构，仅用于五个智能体的功能测试，不对应任何现实主体，也不能作为事实认定材料。

## 文件组成

- `00_采购文件_XX市信息化平台升级建设项目.pdf/.docx`：采购文件，含地域限制和指定品牌两类合规测试条款。
- `A_华诚科技有限公司_投标响应文件.pdf/.docx`：正常对照样本。
- `B_博远信息技术有限公司_投标响应文件.pdf/.docx`：与 C 共享设备、网络、联系人和部分非模板文本。
- `C_新联科技有限公司_投标响应文件.pdf/.docx`：与 B 共享多项信号，并保留共同错字。
- `D_天远科技有限公司_投标响应文件.pdf/.docx`：第 8 页缺少印章，第 12 页使用“天成科技有限公司”测试印章，第 15 页保留签字位。
- `05_电子交易与评审元数据.xlsx`：项目、报价、联系人、文件元数据、网络特征、专家评分和预期风险线索。
- `expected_findings.json`：机器可读的预期发现与安全措辞约束。

## 推荐测试方式

在控制台创建 `full` 核验任务，一次上传采购文件 PDF、A/B/C/D 四份投标 PDF 和 Excel 元数据。项目编号填写 `XXCG-2026-0811`，项目名称填写 `XX市信息化平台升级建设项目`。

建议先使用 PDF 验证印章与签名状态，再使用 DOCX 验证 Office 元数据和正文解析。当前视觉检测只对 PDF 执行。

## 核心验收口径

1. A 为正常对照，不应因与 B/C/D 不同而产生关联异常。
2. B/C 的 IP、MAC、机器码、加密锁号、电话、邮箱和文件作者存在重合；技术方案还包含共同错字。应输出“疑似风险特征，建议人工复核”，不得直接认定串通投标。
3. B/C/D 报价分别为 960、980、1000 万元，形成等差数列。报价规律只能作为组合线索，不能单独定性。
4. D 第 8 页预期 `not_detected`；第 12 页预期 `mismatch` 或 OCR 置信度不足；第 15 页在签名模型未配置时必须为 `not_checked`，不得写成“未签字”。
5. 采购文件中的注册地址和指定品牌条款应由合规审查智能体形成明确或潜在问题，并保留原文证据。
6. 报告生成智能体应汇总明确问题与待人工复核事项，证据链应包含文件、页码、原文或派生检测结果。

## 重新生成

```powershell
.\.venv\Scripts\python.exe .\scripts\build_enterprise_demo.py
```

生成脚本可重复执行，会覆盖同名测试产物，不读取 `.env`，也不会调用外部模型。

任务完成后可执行标准化评测，输出预期发现召回率、证据覆盖率和人工复核覆盖率：

```powershell
.\.venv\Scripts\python.exe scripts\evaluate_enterprise_demo.py data\tasks\Txxxx.json
```
